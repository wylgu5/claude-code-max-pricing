## 限额到底怎么算：一个 5 小时窗口，一个每周上限

两套限制同时运行，缺一不可。

**5 小时滚动窗口**：从你发起第一次请求开始计时，5 小时后滚动刷新。这是高强度会话里最先撞到的墙。用 Sonnet 修 bug、写函数这类轻量任务能撑很久，用 Opus 跑多文件重构则消耗得快得多。

**每周上限**：每 7 天重置一次。哪怕你每个 5 小时窗口都守规矩，只要连续几天重度使用，照样可能撞周限。它才是判断一个套餐够不够用的核心指标。

Pro 的具体量级，第三方测算过“每 5 小时窗口约 10–40 次请求”这样的参考区间。不过官方后来不再公布固定数字，因为实际消耗取决于模型和任务复杂度，这个区间只能当个大概。Max 5x 是 Pro 的 5 倍，Max 20x 是 20 倍，倍数关系是明确的。

## Max 比 Pro 多出来的三样东西

**高峰期优先路由。** 服务器繁忙时，Max 用户的请求排队更靠前。Pro 用户也优先于免费用户，但排在 Max 后面。对白天工作高峰时段重度依赖 Claude Code 的人来说，这一点在体感上比数字更明显。

**Opus 的使用余量。** 两个套餐都能用 Opus，这点经常被误解成“Max 独占”。真正的差别是余量：Pro 的窗口跑几次 Opus 重任务就见底，Max 的配额才撑得起经常性的深度推理任务。

**Fable 的单独每周限制。** 官方帮助文档明确写了 Max 套餐有一项针对 Fable 的独立周限。这是个不太起眼但真实存在的档位差异。

## 撞到限制之后：三条路和两个容易踩的坑

达到限额时，Pro 用户的选项是升级 Max 5x、开通 usage credits 继续用，或者等周期重置；Max 用户类似，5x 可以升 20x。等重置期间会看到剩余额度的提醒，不算难熬，但确实打断节奏。

**坑一：API 额度提示。** Claude Code 在你达到套餐限额时会提示可以通过 API 额度继续使用。注意这是另一套计费系统，走的是 Console 里的余额，如果你在 Console 开了自动充值，余额不足时会自动扣钱买新额度。想严格控制在订阅预算内，提示出现时直接拒绝，用 /status 查剩余配额，等周期重置。想彻底不看到这个提示，可以先执行 claude logout，再只用套餐凭证 claude login，登录过程中不要添加任何 Console 凭证。

**坑二：ANTHROPIC_API_KEY 环境变量。** 如果系统里设了这个变量，Claude Code 会优先用它认证，直接走 API 计费。结果就是订阅额度一动不动、账单却多了几笔。不少人“莫名其妙被扣费”就是这个原因，开始用之前检查一下环境变量。
